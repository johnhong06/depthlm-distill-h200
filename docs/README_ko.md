# depthlm-distill-h200 (한국어)

DepthLM(Pixtral-12B)의 절대 깊이 능력을 교사 답만 라벨로 써서 Qwen2.5-VL-3B 학생(LoRA)에 증류하는 실험이다. Aerodrone H200 서비스(깃허브 이슈 → 젠킨스 → 컨테이너)에서 사람 손 없이 돌도록 묶어 두었다. 기준 문서는 영어 [README](https://github.com/johnhong06/depthlm-distill-h200#readme)이고, 결과 표는 그곳 한 곳에서만 관리한다.

## 한눈에 보기

| | |
|---|---|
| 질문 1: 배분 | 교사 질의 수를 고정했을 때 "이미지 많이 × 이미지당 픽셀 적게"와 "이미지 적게 × 픽셀 많이" 중 무엇이 나은가 |
| 질문 2: 학습 신호 | 교사 답 하나에 대한 CE(`hard`) vs 교사 자릿수 분포에 대한 KL(`soft`) |
| 격자 | 이미지 수 N ∈ {400, 1600, 6400} × 이미지당 픽셀 k ∈ {1, 4, 16}, N·k ≤ 25,600 → 풀·손실마다 중첩 8셀 |
| 풀 | 실내(SUN RGB-D, NYUv2), 주행(KITTI), 혼합(50:50), 각 6,400장 → 풀 3 × 손실 2 = 격자 6개 |
| 라벨 | 풀 픽셀에 대한 DepthLM 12B 답. GT 는 학습에 쓰지 않는다 |
| 평가 | 풀마다 자기 도메인 세트만: 실내 → iBims-1·NYUv2, 주행 → DDAD·nuScenes, 혼합 → 넷 다 |
| 고정 | 픽셀 목록, 교사 라벨, 스텝, 초기화, 셔플 시드, 라벨 형식(소수 첫째), 입력 초점 750, 중간값 복호 |

## 현재 상태

| 풀 | 손실 | 장비 | 풀 버전 | 교사 라벨 | 학습 | 평가 |
|---|---|---|---|---|---|---|
| 혼합 | soft | 로컬 | v5 | 2,544 px 추가 중(로컬) | 대기 (v5 로 재학습) | 로컬 |
| 혼합 | hard | 로컬 | v5 | 2,544 px 추가 중(로컬) | 대기 | 로컬 |
| 실내 | soft | H200 | v4 = v5 | 커밋됨 | 진행 중 | H200 |
| 실내 | hard | H200 | v4 = v5 | 커밋됨 | 다음 | H200 |
| 실외 | soft | H200 | v5 | 커밋됨 (5,640 px 로컬 추가) | 실내 hard 다음 | H200 (주행 평가 팩 필요) |
| 실외 | hard | H200 | v5 | 커밋됨 (5,640 px 로컬 추가) | | H200 (주행 평가 팩 필요) |

순서. H200 은 GPU 한 장으로 한 번에 하나: `grid indoor soft`(진행 중) → `grid indoor hard` → `grid outdoor soft` → `grid outdoor hard`. 작업이 끝날 때마다 관리자에게 `results_<cond>_<pool>.zip` 을 받고 `checkpoints/` 가 들어 있는지 확인한다. 로컬은 실외·혼합 새 교사 라벨 → DDAD·nuScenes 교사 기준선 → 풀 v5 로 `grid mixed soft`·`grid mixed hard` → 학습 전 학생을 네 세트로 평가. 실외 격자는 H200 에서 DDAD·nuScenes 평가까지 한다 (관리자에게 `depthlm_drive_eval.zip` 을 `/app/data` 에 올려 달라고 요청).

풀 v5 는 거의 같은 이미지를 순서 뒤로 보낸 것이다(아래 풀 절). 실내 풀은 해당 이미지가 없어 v4 와 v5 가 같다. 규칙이 생기기 전에 v4 로 학습한 혼합 soft 격자는 로컬에 파일럿으로만 둔다. H200 아카이브에는 주행 세트가 없어 실외 격자는 H200 에서 학습만 한다.

## 판정 규칙 (격자 결과가 나오기 전인 2026-09-29 에 고정)

- 비교: 같은 예산 셀끼리(1,600 질의: N400_k4 vs N1600_k1 / 6,400: N400_k16·N1600_k4·N6400_k1 / 25,600: N1600_k16 vs N6400_k4), 같은 셀의 soft vs hard. 같은 픽셀에서 δ1 차이와 군집 부트스트랩 95 % 구간을 풀의 세트마다 따로 구한다. 군집은 DDAD·nuScenes 에서 장면(장면당 5~6장), iBims-1·NYUv2 에서 사진(사진 한 장이 사실상 장면 하나)이다. 합성 시험에서 장면 단위는 주행 세트의 구간을 사진 단위보다 약 1.5배 넓혔다 — 사진 단위였다면 확신을 과대평가했을 것이다.
- 풀의 모든 세트가 같은 방향이고 구간이 모두 0 을 빼면 결론으로 주장한다. 방향은 같은데 일부만 0 을 빼면 약한 근거, 방향이 갈리면 세트에 따라 다름으로 보고하고 주장하지 않는다.
- 혼합 풀은 실내 두 세트와 주행 두 세트에 각각 적용하고, 두 도메인이 모두 같을 때만 풀 결론으로 주장한다.
- 다른 도메인 점수는 배분·손실이 아니라 도메인 차이를 재므로 계산하지 않는다. 부정 결과도 모두 보고한다.
- 판정 스크립트: `experiments/32_decide.py --pool <pool>` 가 한 풀의 soft·hard 결과에 규칙을 적용해 `tables/decision_<pool>.md` 를 쓴다(DDAD 차체 영역 제외 민감도 값 포함). 주장하지 않는 경우는 "세트 의존"(방향이 갈리고 하나라도 0 제외)과 "근거 없음"(모든 구간이 0 포함)으로 나눠 적는다.

## 실행

H200 서비스 사용법(신청, 요청서, 컨테이너 경로, 데이터 전달, 겪은 문제)은 [H200 사용법 페이지](https://johnhong06.github.io/depthlm-distill-h200/)에 정리.

| 명령 | GPU | 내용 |
|---|---|---|
| `bash run.sh smoke` | 1 | 합성 풀로 30스텝 학습 + 3픽셀 평가, 약 20분 |
| `bash run.sh label <pool>` | 7 | 커밋된 라벨에 없는 픽셀만 교사로 라벨링. 결과 parquet 는 `pools/<pool>/` 에 커밋 |
| `bash run.sh grid <pool> <soft\|hard>` | 7 | 8셀 학습 → 풀의 평가 세트로 평가 → `results_<cond>_<pool>.zip`(checkpoints 포함) |

- 데이터: 30 GB 아카이브(풀 이미지, 실내 평가 세트, 교사 가중치)와 566 MB 주행 평가 팩 `depthlm_drive_eval.tar`(+ `.sha256`)를 `/app/data` 아래에 두면 run.sh 가 찾아서 검증하고 푼다.
- H200 작업 사이에는 아무것도 남지 않으므로 라벨은 저장소에 커밋하고, 격자는 한 작업 안에서 학습과 평가를 끝낸다.

## 풀

| 풀 | 이미지 / 장면 | 구성 | 교사 라벨 (풀마다 44,800 px) |
|---|---|---|---|
| 혼합 | 6,400 / 3,684 | 실내 3,200 (SUN RGB-D 2,979, NYUv2 221) + 주행 3,200 (KITTI raw 2,070, 2015 400, 2012 388, depth-selection 342) | v4 42,256 px(로컬, 그중 1,160 은 H200) + v5 2,544 px(로컬) |
| 실내 | 6,400 / 5,674 | SUN RGB-D 5,834, NYUv2 566 | H200 |
| 실외 | 6,400 / 509 | KITTI raw 4,929, depth-selection 683, 2015 400, 2012 388 | v4 39,160 px(H200) + v5 5,640 px(로컬) |

- 이미지마다 픽셀 16개를 미리 정해 두고(5 % 테두리 제외 균등, 시드 = 이미지 경로) 셀은 앞 N장의 앞 k개를 쓴다. 그래서 한 풀의 모든 셀이 같은 라벨을 읽는다.
- **풀 v5 (2026-09-29)**: 도메인마다 순서대로 훑으며, 이미 남긴 이미지 중 dHash 거리 ≤ 10 이고 32×32 회색조 상관 > 0.9 인 것이 있으면 그 도메인의 뒤로 보내고, 위치마다 원래 도메인의 다음 이미지로 채운다(혼합 풀 50:50 유지). DepthLM 도 "아주 비슷한 영상 프레임"은 도움이 안 된다며 일부만 썼는데 규칙은 밝히지 않았다 — 그 단계를 명시한 버전이다. 실외 1,365장(정차·저속 raw 프레임, 0.1초 간격 `_10`/`_11` 쌍으로 들어간 KITTI 2012·2015), 혼합 주행 749장이 뒤로 갔고 실내는 0장. 앞 N = 400 / 1,600 / 6,400 장의 서로 다른 이미지는 실외 372 / 1,130 / 5,035 → 400 / 1,600 / 5,035, 혼합 391 / 1,388 / 5,651 → 400 / 1,600 / 5,651. 이미지 집합·픽셀 좌표·N = 6,400 셀은 그대로다.
- **한계**: 주행 풀의 장면 509개는 실제 장소 수보다 많다. KITTI 2012·2015 이미지를 한 장씩 별도 장면으로 세는데, 실외 풀의 788장 중 249장이 풀 안의 raw 프레임과 같은 장소다(혼합 176장). 장소 단위로는 N = 1,600 이후 새 장소가 거의 늘지 않으므로(약 320곳) 주행 풀의 N·k 비교는 이 한계와 함께 보고한다.
- **풀 v4 (2026-09-23)**: NYUv2 는 방마다 약 3장이라 평가 200장이 속한 195개 방을 장면 단위로 풀에서 뺐다. 어느 풀에도 평가 세트의 이미지나 장면은 없다.

## 평가 세트

| 도메인 | 세트 | 쓰는 풀 | 이미지 / 픽셀 | 비고 |
|---|---|---|---|---|
| 실내 | NYUv2 | 실내, 혼합 | 200 / 2,000 | 같은 데이터셋이지만 방 단위로 풀에서 제외 |
| 실내 | iBims-1 | 실내, 혼합 | 100 / 3,000 | 풀에 없음 |
| 주행 | DDAD | 주행, 혼합 | 250 / 2,500 | 다른 차량·국가, 낮. 풀에 없음 |
| 주행 | nuScenes | 주행, 혼합 | 250 / 2,500 | DepthLM 의 실제 평가 구간 nuScenes v1.0-mini: 10장면(낮 7, 밤 3), 교사 학습에서 제외 |

- GT 는 모두 카메라 중심까지의 유클리드 거리(프롬프트가 묻는 값). DepthLM 의 DDAD·nuScenes 스크립트는 z 깊이를 써서 두 주행 세트는 z 도 저장하고, 교사를 논문값(DDAD 0.670, nuScenes 0.819)과 비교할 때만 쓴다. ETH3D 는 판정에 쓰는 풀이 없어 더 평가하지 않는다.
- DDAD·nuScenes 는 DepthLM 논문 표에 학습 전 Qwen2.5-VL-3B, 같은 백본을 GT 1,600만 장으로 학습한 DepthLM-3B, 순수 비전 모델과 함께 있어 논문 수치와 나란히 놓을 수 있다. 둘 다 DepthLM 선정 스크립트를 따르고 250장 × 10픽셀(시드 0, 마커용 테두리 10 px 제외)로 부분 표본을 뽑는다 — 같은 값을 다른 무작위 픽셀로 추정한다.
- DDAD(`experiments/41_build_ddad.py`): val 50장면, 카메라 6대, LiDAR 투영(픽셀당 최근접), 장면당 (샘플, 카메라) 5쌍. 공식 절차는 자차를 가리지 않아 전면이 아닌 카메라 아래쪽 1/4 의 픽셀 약 절반이 차체 위다 → 논문과 비교하려고 그대로 두고, 그 영역을 뺀 민감도 값을 함께 보고한다.
- nuScenes(`experiments/43_build_nuscenes.py`): v1.0-mini 10장면(404 샘플) × 카메라 6대. 공개 `curate_nuscenes_eval.py` 는 trainval 마지막 5 % 를 쓰지만, 제1저자가 [이슈 #17](https://github.com/facebookresearch/DepthLM_Official/issues/17)에서 공개 파일의 실수이고 실제 평가는 mini 였다고 확인했다(학습 스크립트도 mini 장면을 뺀다). 처음 만든 공개 구간(43장면, 전부 밤)에서는 교사가 0.640 으로 논문 0.819 와 맞지 않았고, 이것으로 차이를 찾았다. 2,424 쌍 중 250쌍(밤 84장).

## 로컬 실행

```bash
DATA_ROOT=/path/to/data bash run.sh grid mixed soft
DATA_ROOT=/path/to/data OUT_ROOT=/path/with/checkpoints bash run.sh eval outdoor soft   # H200 zip 의 어댑터 평가
python experiments/32_decide.py --pool indoor --soft_root <OUT_ROOT> --hard_root <OUT_ROOT>   # 판정표
```
