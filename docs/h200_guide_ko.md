# Aerodrone H200 사용법

깃허브에 실행 코드를 올리고 요청 이슈를 하나 쓰면, 서버가 그 코드를 컨테이너에서 돌리고 화면 출력을 이슈 댓글로 돌려준다. 이 문서는 신청부터 결과 회수까지의 절차와, 실제로 써 보며 확인한 서버의 동작을 정리한 것이다. 이 저장소(depthlm-distill-h200)를 돌리는 방법은 [README](../README.md)에 있다.

## 1. 전체 흐름

1. [항공드론혁신융합대학 공간/기자재 사용신청](https://www.aerodrone.ac.kr/ko/support/application/rent/application/4)에서 H200 사용 기간을 신청한다. 시작 하루 전까지 신청해야 하고 1인 1건이다.
2. 개인 이메일로 온 H200 깃허브 조직 초대를 수락한다.
3. 실행 코드를 개인 깃허브 저장소에 push 한다. 저장소는 공개이거나 사업단이 접근할 수 있어야 한다.
4. `Aerodrone-H200/gpu-request` 저장소에 요청 이슈를 쓴다. 이슈는 승인된 기간 안에서만, 종료 30분 전까지 낼 수 있다.
5. 젠킨스가 저장소를 클론하고 컨테이너에서 실행 명령어를 돌린다.
6. 작업이 끝나면 화면 출력(최대 65,000자)이 이슈 댓글로 달리고 컨테이너는 삭제된다.
7. `/app/output` 에 남긴 결과 파일은 관리자에게 요청해서 받는다.

## 2. 요청서 작성

| 항목 | 값 |
|---|---|
| 사용자 ID | 깃허브 아이디 |
| GitHub 링크 | `https://github.com/<아이디>/<저장소>.git` |
| 코드 실행 명령어 | 한 줄 명령. 예: `bash run.sh smoke` |
| 사용할 이미지 | `pytorch/pytorch:latest`. 실제로 배포되는 이미지는 `kau/pytorch-master:latest`(torch 2.11, Python 3.10)다 |
| 사용 언어 | `Python` |
| GPU 할당량 | `1` = GPU 1/7 조각(약 16 GB), `7` = GPU 한 장 통째(141 GB) |

- 짧은 확인 작업은 `1`, 큰 모델이나 병렬 학습은 `7` 로 낸다.
- `7` 은 조각 7개가 아니라 GPU 한 장이다. 한 장 안에서 프로세스를 여러 개 동시에 띄우면 된다.
- 설치할 패키지를 적는 칸은 없다. 필요한 패키지는 코드가 시작할 때 스스로 설치해야 한다.

## 3. 요청 후 진행 과정

이슈를 올리면 댓글이 다음 순서로 달린다.

1. 사용자 확인 → 권한 확인(소속 그룹) → GPU 할당량 확인(요청량이 그룹 한도 안인지) → 1차 검증
2. 예약 검증: 신청해 둔 사용 기간과 현재 시각을 대조한다.
3. 큐 대기: 자원이 사용 중이면 앞 작업이 끝난 뒤 순서대로 자동 시작된다.
4. 배포 완료: Pod 이름과 Grafana 모니터링 링크가 달린다. 실행 중에는 이 링크로 GPU·메모리 사용량만 볼 수 있고 로그는 볼 수 없다.
5. 작업이 끝나면 화면 출력이 댓글로 달린다.

## 4. 컨테이너 안의 경로

| 경로 | 쓰기 | 용도 | 작업 사이에 남는가 |
|---|---|---|---|
| `/app/data` | 읽기 전용 | 관리자가 넣어 준 데이터·가중치 | 남는다 |
| `/app/output` | 가능 | 결과 파일 전용 | 남지 않는다 (작업마다 새 볼륨) |
| `/app/scratch` | 가능 | 작업 공간. 저장소 클론과 HF 캐시가 여기 생긴다 | 남지 않는다 |

2026-09-28 실측 기준으로 `/app/data` 와 `/app/output` 은 같은 볼륨을 써서 여유가 약 103 GB였고, `/app/scratch` 는 따로 약 950 GB였다.

- **한 작업이 만든 파일은 다음 작업이 보지 못한다.** `/app/output` 과 `/app/scratch` 모두 작업마다 비어서 시작한다. 다음 작업에 넘겨야 하는 중간 결과(예: 라벨 파일)는 저장소에 커밋해야 한다.
- 그래서 학습과 평가처럼 이어지는 단계는 한 작업 안에서 끝내야 한다. 결과 볼륨이 유지되는 로컬에서만 단계를 나눠 돌릴 수 있다.
- `/app/output` 에는 결과만 둔다. 압축 해제본이나 모델 캐시가 들어가 100 GB를 넘으면 실험이 멈춘다.
- 결과는 작업 끝에 zip 으로 묶어 `/app/output` 에 둔다.

## 5. 데이터와 가중치 전달

- 서버에서 직접 내려받을 수 없는 데이터나 가중치는 관리자에게 파일로 전달한다. 관리자가 `/app/data/<폴더>` 에 넣어 준다.
- 큰 파일은 2 GB 조각으로 나누고 SHA256 체크섬을 함께 보낸다. 구글 드라이브에 브라우저로 올리면 30 GB에 21시간이 걸렸고, rclone 으로 조각을 병렬 업로드하면 약 15분이었다.
- 관리자가 드라이브 폴더를 통째로 받으면 조각이 zip 으로 묶여 올 수 있다. 코드는 zip 안의 조각도 찾아 풀 수 있어야 한다.
- 압축은 코드가 실행 중에 푼다. `/app/data` 는 읽기 전용이므로 `/app/scratch` 에 풀어야 하고, 30 GB를 푸는 데 약 2분 걸렸다. 작업마다 다시 풀어야 한다.
- 허깅페이스 공개 모델은 토큰 없이 받는다. 토큰이 필요한 모델은 가중치 자체를 관리자에게 전달한다.

## 6. 꼭 지킬 것

- **토큰과 비밀번호는 저장소나 이슈에 적지 않는다.** 둘 다 공개라 스캐너에 걸려 토큰이 바로 무효가 된다. 관리자도 `/app/data` 에 비밀 파일을 두는 것을 원하지 않는다.
- 처음에는 항상 몇 분짜리 스모크 테스트로 환경·데이터·경로를 확인한 뒤 본 실험을 낸다.
- 화면 출력은 요약만 찍는다. 65,000자를 넘으면 잘리므로 전체 로그는 `/app/output` 에 파일로 남겨야 한다.
- 긴 실험은 단계별 작업으로 나눈다. 모든 단계를 한 작업에 넣었던 실행이 35시간 만에 강제 종료됐고, 화면 출력만으로는 어디까지 진행됐는지 알 수 없었다.
- 같은 명령을 다시 냈을 때 끝난 부분을 건너뛰고 이어서 하도록 코드를 짠다. 다만 결과 볼륨이 매번 비워지므로, 실제로 이어지는 것은 저장소에 커밋해 둔 것뿐이다.
- 컨테이너에서는 `nvidia-smi` 권한이 없을 수 있다. GPU 메모리는 torch 로 확인한다.

## 7. 결과 받기

- 결과 파일은 작업이 끝날 때마다 관리자에게 요청해야 한다. 이슈 번호나 Pod 이름과 함께 `/app/output` 안의 파일 이름을 적어 요청한다.
- 고정 IP를 받아 결과가 로컬로 바로 오게 하는 방법을 진행 중이다. 이 방법이 열리면 따로 요청할 필요가 없어진다.

## 8. 겪은 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 허깅페이스 토큰이 무효로 실패 | 토큰을 공개 이슈 명령어에 적었다 | 토큰을 쓰지 않고 가중치를 파일로 전달 |
| 스모크 테스트에서 이미지 파일이 없음 | `.gitignore` 의 `data/` 규칙이 `smoke/data/` 까지 제외 | 규칙을 `/data/` 로 바꿔 커밋 |
| GPU 메모리를 읽지 못함 | 컨테이너에 `nvidia-smi` 권한이 없다 | torch 로 메모리 판정 |
| 기본 이미지에 패키지가 없음 | `peft` 등이 설치돼 있지 않다 | 코드가 시작할 때 requirements 를 설치 |
| 드라이브 업로드 21시간 | 브라우저 업로드 속도 제한 | 2 GB 조각 16개를 rclone 으로 병렬 업로드(약 15분) |
| `/app/output` 이 100 GB를 넘어 실험 종료 | `/app/data` 가 읽기 전용이라 압축 해제본과 모델 캐시가 `/app/output` 으로 갔다 | 압축은 `/app/scratch` 에 풀고 `/app/output` 에는 결과만 둔다 |
| 다음 작업이 이전 결과를 찾지 못함 | `/app/output`·`/app/scratch` 가 작업마다 비워진다 | 중간 결과는 저장소에 커밋하고, 이어지는 단계는 한 작업에서 끝낸다 |
| 전체 실행이 35시간 만에 강제 종료 | 모든 단계를 한 작업에 넣었다 | 단계별 작업으로 나눈다 |

## 9. 이 저장소에서의 사용 예

| 명령 | GPU | 내용 |
|---|---|---|
| `bash run.sh check` | 1 | 경로별 쓰기 가능 여부와 여유 공간을 확인한다. 1분 이내 |
| `bash run.sh smoke` | 1 | 합성 이미지 40장으로 30스텝 학습과 3픽셀 평가를 한다. 약 20분 |
| `bash run.sh label <pool>` | 7 | 교사 모델로 라벨을 만든다. 결과 parquet 는 저장소에 커밋해야 다음 작업이 쓴다 |
| `bash run.sh grid <pool> <soft\|hard>` | 7 | 8셀 학습과 평가를 한 작업에서 끝내고 `results_<cond>_<pool>.zip` 을 남긴다 |

작업이 끝나면 `results_<cond>_<pool>.zip` 을 요청하고, zip 안에 `checkpoints/` 가 들어 있는지 확인한다.
