## 전체 흐름 {#flow}

1. [항공드론혁신융합대학 공간/기자재 사용신청](https://www.aerodrone.ac.kr/ko/support/application/rent/application/4)에서 사용 기간 신청 — 시작 하루 전까지, 1인 1건
2. 개인 이메일로 온 H200 깃허브 조직 초대 수락
3. 실행 코드를 개인 저장소에 push (공개 또는 사업단이 접근 가능한 저장소)
4. `Aerodrone-H200/gpu-request` 에 요청 이슈 작성 — 승인된 기간 안에서, 종료 30분 전까지
5. 젠킨스가 저장소를 클론해 컨테이너에서 명령 실행
6. 끝나면 화면 출력(최대 65,000자)이 댓글로 달리고 컨테이너는 삭제됨
7. `/app/output` 결과 파일은 관리자에게 요청해서 받음

## 요청서 작성 {#request}

| 항목 | 값 |
|---|---|
| 사용자 ID | 깃허브 아이디 |
| GitHub 링크 | `https://github.com/<아이디>/<저장소>.git` |
| 코드 실행 명령어 | 한 줄 명령. 예: `bash run.sh smoke` |
| 사용할 이미지 | `pytorch/pytorch:latest` (실제 배포 이미지는 `kau/pytorch-master:latest`, torch 2.11 · Python 3.10) |
| 사용 언어 | `Python` |
| GPU 할당량 | `1` = GPU 1/7 조각(약 16 GB), `7` = GPU 한 장(141 GB) |

- 짧은 확인은 `1`, 큰 모델이나 병렬 학습은 `7`
- `7` 은 조각 7개가 아니라 GPU 한 장. 그 안에서 프로세스 여러 개를 동시에 띄우면 됨
- 패키지를 적는 칸은 없음 → 코드가 시작할 때 직접 설치해야 함

## 요청 후 진행 과정 {#progress}

이슈를 올리면 댓글이 이 순서로 달림.

1. 사용자 → 권한(소속 그룹) → GPU 할당량(그룹 한도) 확인, 1차 검증
2. 예약 검증 — 신청한 사용 기간 안인지 확인
3. 큐 대기 — 자원이 차 있으면 앞 작업이 끝난 뒤 자동 시작
4. 배포 완료 — Pod 이름과 Grafana 링크가 달림. Grafana 로는 GPU·메모리 사용량만 보이고 로그는 안 보임
5. 끝나면 화면 출력이 댓글로 옴

## 컨테이너 안의 경로 {#paths}

| 경로 | 쓰기 | 용도 | 다음 작업까지 남는가 |
|---|---|---|---|
| `/app/data` | 읽기 전용 | 관리자가 올려 준 데이터·가중치 | 남음 |
| `/app/output` | 가능 | 결과 파일 전용 | 안 남음 (작업마다 새 볼륨) |
| `/app/scratch` | 가능 | 작업 공간. 저장소 클론과 HF 캐시가 여기 생김 | 안 남음 |

여유 공간(2026-09-28 기준): `/app/data`·`/app/output` 공용 약 103 GB, `/app/scratch` 약 950 GB.

<p class="no">작업끼리 파일이 이어지지 않음. 이전 작업이 만든 파일은 다음 작업에서 안 보임.</p>

- 다음 작업에 넘길 중간 결과(예: 라벨 파일)는 저장소에 커밋
- 학습 → 평가처럼 이어지는 단계는 한 작업 안에서 끝내야 함
- `/app/output` 에는 결과만. 압축 해제본이나 모델 캐시가 들어가 100 GB를 넘으면 실험이 멈춤
- 결과는 zip 으로 묶어 `/app/output` 에 두기

## 데이터와 가중치 전달 {#data}

- 서버에서 직접 못 받는 데이터·가중치는 관리자에게 파일로 전달 → `/app/data/<폴더>` 에 올려 줌
- 큰 파일은 2 GB 조각 + SHA256 체크섬으로. 브라우저 업로드는 30 GB에 21시간, rclone 병렬 업로드는 약 15분
- 드라이브 폴더째 받으면 조각이 zip 으로 묶여 올 수 있음 → zip 안의 조각도 풀 수 있게 작성
- 압축은 실행 중에 `/app/scratch` 에 풀기 (`/app/data` 는 읽기 전용). 30 GB에 약 2분, 작업마다 다시 풀어야 함
- 허깅페이스 공개 모델은 토큰 없이 받음. 토큰이 필요한 모델은 가중치를 관리자에게 전달

## 꼭 지킬 것 {#rules}

<p class="no">토큰·비밀번호는 저장소나 이슈에 절대 적지 않기.</p>

- 저장소와 이슈 모두 공개라 스캐너에 걸려 바로 무효화됨. 관리자도 `/app/data` 에 비밀 파일 두는 걸 원하지 않음
- 본 실험 전에 몇 분짜리 스모크 테스트로 환경·데이터·경로부터 확인
- 화면 출력은 요약만. 65,000자를 넘으면 잘리니 전체 로그는 `/app/output` 에 파일로
- 긴 실험은 단계별로 나누기. 한 작업에 다 넣은 실행이 35시간 만에 강제 종료됐고, 어디까지 됐는지 알 수 없었음
- 다시 요청했을 때 끝난 부분은 건너뛰도록 작성. 단, 결과 볼륨이 매번 비워지므로 실제로 이어지는 건 저장소에 커밋한 것뿐
- 컨테이너에서 `nvidia-smi` 권한이 없을 수 있음 → GPU 메모리는 torch 로 확인

---

## 결과 받기 {#results}

- 작업이 끝날 때마다 관리자에게 요청. 이슈 번호(또는 Pod 이름)와 `/app/output` 안의 파일 이름을 같이 적기
- 고정 IP로 결과를 로컬에 바로 받는 방법 진행 중. 열리면 따로 요청할 필요 없음

## 겪은 문제와 해결 {#issues}

| 문제 | 원인 | 해결 |
|---|---|---|
| 허깅페이스 토큰 무효 | 토큰을 공개 이슈에 적음 | 토큰 없이 가중치를 파일로 전달 |
| 스모크 테스트에서 이미지 없음 | `.gitignore` 의 `data/` 가 `smoke/data/` 까지 제외 | `/data/` 로 수정 |
| GPU 메모리 확인 실패 | `nvidia-smi` 권한 없음 | torch 로 확인 |
| 기본 이미지에 패키지 없음 | `peft` 등 미설치 | 시작할 때 requirements 설치 |
| 드라이브 업로드 21시간 | 브라우저 업로드 속도 제한 | 2 GB × 16조각을 rclone 으로 병렬 업로드 (약 15분) |
| `/app/output` 100 GB 초과로 중단 | `/app/data` 가 읽기 전용이라 해제본·캐시가 `/app/output` 으로 감 | 압축은 `/app/scratch` 에, `/app/output` 에는 결과만 |
| 다음 작업이 이전 결과를 못 찾음 | `/app/output`·`/app/scratch` 가 작업마다 비워짐 | 중간 결과는 저장소에 커밋, 이어지는 단계는 한 작업에서 |
| 35시간 만에 강제 종료 | 모든 단계를 한 작업에 넣음 | 단계별 작업으로 분리 |

## 사용 예 {#example}

이 저장소의 `run.sh` 기준.

| 명령 | GPU | 내용 |
|---|---|---|
| `bash run.sh check` | 1 | 경로별 쓰기 가능 여부·여유 공간 확인 (1분 이내) |
| `bash run.sh smoke` | 1 | 합성 이미지 40장으로 30스텝 학습 + 3픽셀 평가 (약 20분) |
| `bash run.sh label <pool>` | 7 | 교사 모델로 라벨 생성. 결과 parquet 는 저장소에 커밋해야 다음 작업에서 씀 |
| `bash run.sh grid <pool> <cond>` | 7 | 학습·평가를 한 작업에서 끝내고 `results_<cond>_<pool>.zip` 생성 (`<cond>` = `soft` / `hard`) |

끝나면 `results_<cond>_<pool>.zip` 을 요청하고, 안에 `checkpoints/` 가 있는지 확인.
